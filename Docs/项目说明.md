# atk_f103 · 项目说明

> STM32F103ZET6（正点原子 精英版 V2）+ 温湿度（DHT11 / SHT30）+ 光敏 → LCD 本地显示
> 可选：ESP8266 → OneNET 环境数据上云
> 工程基于 **STM32CubeMX 6.18 + STM32Cube FW_F1 V1.8.7 + HAL 库 + Keil MDK (Arm Compiler 6)**
>
> **验收状态：已验收完毕（2026-09-22），详见 §9 验收记录。**

---

## 0. 配置总览（都在 `User\App\app_config.h`）

### 0.1 温湿度传感器二选一

```c
#define APP_SENSOR_TH   2   /* 0=只用 DHT11  1=只用 SHT30  2=自动探测(先 SHT30, 再 DHT11) */
```

| 取值 | 说明 |
|---|---|
| `0` | 只用 DHT11（PG11 单总线） |
| `1` | 只用 SHT30（PB6=SCL / PB7=SDA 软件 I2C） |
| `2`（默认） | 开机自动探测，**SHT30 优先**；识别结果打印到串口并显示在 LCD 最后一行 |

### 0.2 界面字号

```c
#define APP_UI_FONT_TITLE   32      /* 标题字号上限 */
#define APP_UI_FONT_DATA    32      /* 正文字号上限 */
```

字库只支持 **12 / 16 / 24 / 32** 四种 ASCII 字号。程序按**屏幕实际高度**和**实际要显示的行数**
在四种字号里挑一个放得下的最大值，再受上面两个上限约束。

关掉联网时 `WiFi / Cloud / Sent` 三行不显示（行号在 `ui_setup()` 里动态分配），
省下的高度全部让给字号：

| 屏幕（横屏） | `APP_ENABLE_NET=0` | `APP_ENABLE_NET=1` |
|---|---|---|
| 3.5" 480×320 | **32 / 32** | **32 / 32** |
| 2.8" 320×240 | **32 / 32** | 24 / 16 |
| 7"  800×480 | 32 / 32 | 32 / 32 |

开机串口会打印 `LCD  : id=xxxx  480x320  font=32/32`，可直接确认实际生效的字号。

### 0.3 报警阈值（两级：舒适区 / 危险区）

```c
/* ---- 危险区：超出才真正报警（蜂鸣器 + 整屏闪烁 + 红色） ---- */
#define APP_TEMP_MIN_X10            100     /* 10.0 ℃ 以下 */
#define APP_TEMP_MAX_X10            320     /* 32.0 ℃ 以上 */
#define APP_HUMI_MIN_X10            250     /* 25.0 %RH 以下 */
#define APP_HUMI_MAX_X10            850     /* 85.0 %RH 以上 */
#define APP_LUX_MIN_CDM2            0       /* 不做下限判断 */
#define APP_LUX_MAX_CDM2            (APP_LUX_FULL_SCALE_CDM2 - 100)   /* 光敏饱和 */

/* ---- 舒适区：超出只在 LCD 上变黄 + warnT/warnH/warnL，不响 ---- */
#define APP_COMFORT_TEMP_MIN_X10    180     /* 18.0 ℃ */
#define APP_COMFORT_TEMP_MAX_X10    280     /* 28.0 ℃ */
#define APP_COMFORT_HUMI_MIN_X10    400     /* 40.0 %RH */
#define APP_COMFORT_HUMI_MAX_X10    700     /* 70.0 %RH */
#define APP_COMFORT_LUX_MIN_CDM2    100     /* 100 cd/m² */
#define APP_COMFORT_LUX_MAX_CDM2    4000    /* 4000 cd/m² == 光敏读数 20 */

#define APP_LUX_FULL_SCALE_CDM2     20000   /* 光敏读数 100 相当于多少 cd/m² */

/* ---- 报警时序 ---- */
#define APP_ALARM_TIME_MS  10000    /* 单次报警持续时间 */
#define APP_ALARM_GAP_MS   10000    /* 两次报警之间的静默时间 */

/* ---- 误报抑制：只定义“什么时候才算越界 / 才算恢复” ---- */
#define APP_ALARM_CONFIRM_MS    3000    /* 连续越界 3 秒才确认；0 = 立即生效 */
#define APP_ALARM_HYST_TEMP_X10 5       /* 迟滞 0.5 ℃ */
#define APP_ALARM_HYST_HUMI_X10 20      /* 迟滞 2.0 %RH */
#define APP_ALARM_HYST_LUX_CDM2 100     /* 迟滞 100 cd/m² */

/* ---- 报警时的整屏闪烁（60 岁以上约三分之一有听力损失） ---- */
#define APP_ALARM_FLASH         1       /* 1 = 整屏“红底白字 ↔ 白底彩字”交替闪 */
#define APP_ALARM_FLASH_MS      400     /* 闪烁半周期(ms) */
```

**为什么要分两级**：老人居室冬天 16~20 ℃、夏天空调房 26~28 ℃ 都属正常，
把"舒适区"直接当报警线，设备会天天响，老人会**直接把电源拔掉，报警功能归零**。
真正的危险点是医学意义上的：低温有低体温风险（独居老人冬天舍不得开暖气，这才是最该报的），
高温有中暑/脱水风险，湿度极端值对应呼吸道不适与结露发霉。
所以舒适区只做**黄色提示**，危险区才**响**。

| 参数 | 舒适区（黄字提示，不响） | 危险区（蜂鸣器 + 整屏闪） |
|---|---|---|
| 温度 | 18.0 – 28.0 ℃ | < 10.0 或 > 32.0 ℃ |
| 湿度 | 40 – 70 %RH | < 25 或 > 85 %RH |
| 光照 | 100 – 4000 cd/m²（= 光敏读数 20） | 光敏量程打满（光敏读数 100） |

> `APP_COMFORT_xxx` 必须落在危险区以内（`DANGER_MIN ≤ COMFORT_MIN < COMFORT_MAX ≤ DANGER_MAX`），
> 程序不检查这个约束，填反了会出现"只提示不报警"的怪现象。

行为：

- 任一参数**连续越界 `APP_ALARM_CONFIRM_MS`（3 秒）** 后：
  - 超出**危险区** → 蜂鸣器连续响 10 秒 + **LCD 整屏闪烁**（红底白字 ↔ 白底彩字）；
  - 只超出**舒适区** → 对应数值行与 `Alarm` 行变**黄**并显示 `warnT` / `warnH` / `warnL`，**不响**；
- 危险区报警 10 秒到自动停，静默 10 秒；仍越界则再响 10 秒，如此反复；
- 报警期间按 **KEY0（PE4）** → 立即停，并消音到**所有参数回到舒适区**为止
  （否则 0.5 秒后又会响，KEY0 就失去意义），整屏闪烁同时停止、回到白底；
- 完全回到舒适区 → 自动解除消音，下次越界可再次报警。

确认窗与迟滞是**误报抑制**：这类居家监护设备最大的敌人是误报 —— 老人被反复吵到会直接拔电源，
一次误报的伤害比十次漏报还大。确认窗滤掉瞬时尖峰（手电扫过、开关门、传感器抖动）；
迟滞让数值卡在阈值附近时不会"响 10 秒停 10 秒"无限循环、也不会黄字一闪一闪。
把 `APP_ALARM_CONFIRM_MS` 填 0 即恢复立即生效。

LCD 的 `Alarm` 行：危险区用大写记号 `TEMP` / `HUMI` / `LIGHT`（组合用 `+` 连接），
舒适区外用小写 `warnT` / `warnH` / `warnL`，一眼能分清"在响"和"只是提示"。

| `Alarm` 行颜色 | 含义 |
|---|---|
| 蓝 | 舒适区内，一切正常 |
| 黄 | 只超出舒适区，**不响** |
| 红 | 超出危险区，正在响 |
| 黑 | 超出危险区但已消音 / 间歇期 |

对应数值行同样**红=危险区，黄=舒适区外，蓝=正常**。
（红底闪烁期间文字自动换成白/黄，保证在红底上依然看得清。）

> ⚠️ **光照单位说明**：板载 LS1 是光敏电阻，`lsens_get_val()` 给出的是 0~100 的**相对光强**，
> 不是标定过的照度计。代码用 `APP_LUX_FULL_SCALE_CDM2`（默认 20000，表示光敏读数 100 相当于
> 多少 cd/m²）把 cd/m² 阈值换算到光敏读数，即光敏读数 1 ↔ 200 cd/m²。
> 光照的黄线（4000 cd/m² ↔ 光敏读数 20）**正好等于旧版"2000 cd/m² + FULL_SCALE 10000"那条会响的线**：
> 也就是说同样一次强光，现在只变黄不再响，这是本轮改动的可见差异之一。
>
> 危险上限写成 `(APP_LUX_FULL_SCALE_CDM2 - 100)` 是有意的：判断用的是 `>`，
> 取"量程减一点"才能在读数打满的瞬间触发，而且标定后改 `FULL_SCALE` 它会自动跟着走。
> 标定方法：用手机照度计 App 对着同一光源，同时看串口打印的 `lsens=` 读数，
> 用 `照度 × (100 / lsens)` 反推该宏。**要真正测量照度请改用 BH1750 等数字照度传感器。**

### 0.4 联网开关与断线检测

```c
#define APP_ENABLE_NET        1       /* 0 = 只做采集 + LCD 显示；1 = 打开 ESP8266 + OneNET 上报 */
#define APP_PING_PERIOD_MS    30000   /* MQTT 心跳周期(ms)，必须小于 MQTT_KEEPALIVE_S */
#define MQTT_PING_TIMEOUT_MS  3000    /* 发 PINGREQ 后等 PINGRESP 的超时(ms) */
#define APP_PING_FAIL_MAX     2       /* 连续几次心跳无应答就判定链路断了 */
#define APP_NET_RETRY_MS      15000   /* 联网失败后的重试间隔(ms) */
#define APP_NET_FAIL_RESCAN   4       /* 连续失败几次后允许重新全扫描波特率 */
```

| 取值 | 行为 | 编译体积（Code + RO-data） |
|---|---|---|
| `0` | 完全不碰 ESP8266 / OneNET，界面只显示 Temp / Humi / Light / 传感器状态 | ≈ 55.5 KB |
| `1` | 走完整联网 + MQTT 上报流程，多出 WiFi / Cloud / Sent 三行 | ≈ 62.0 KB |

**两种取值下，采集与显示都永远工作。** 联网是"尽力而为"：用状态机实现，每次主循环只推进一步，
任何一步失败只更新屏幕上对应的状态行并在 15 秒后重试，**绝不会像早期的阻塞式写法那样卡住界面**。
联网阻塞等待期间（`AT+CWJAP` 最长 20 s、`AT+CIPSTART` 最长 15 s、等 CONNACK 5 s）
由驱动每 20 ms 回调一次 `app_poll()`，蜂鸣器节拍、KEY0 消音、报警闪烁、看门狗喂狗全部照常。

**断线检测（`APP_ENABLE_NET = 1` 时）**

上线以后主循环每 20 ms 排空 USART3 接收缓冲（`mqtt_poll_rx()`），并识别两类事件：

| 事件 | 来源 | 处理 |
|---|---|---|
| `CLOSED` / `WIFI DISCONNECT` | 模块主动上报的 URC | 立即重连 |
| 连续 2 次收不到 `PINGRESP` | 30 秒一次的心跳无应答 | 立即重连 |

判定故障后走完整重连流程：`+++` 退出透传 → `AT+CIPCLOSE` → 等 `APP_NET_RETRY_MS` →
**`AT+RST` 复位模块 + 重新扫描波特率** → 重新 `CWJAP` / `CIPSTART` / MQTT `CONNECT`。
最坏约 65 秒内必被察觉并开始重连。

> **为什么必须排空接收缓冲**：旧版上线以后没有任何代码读串口，768 字节环形缓冲只涨不落，
> 满了之后模块发来的 `CLOSED` / `PINGRESP` 会被 ISR **静默丢弃**；同时 `mqtt_ping()`
> 只判断"串口写成功了没有"（那几乎永远成功），等于没有保活检测。结果是云端断了以后
> 本地一路显示 `Cloud : online`、`Sent` 还在往上涨，实际早就没数据了。
> 对监护独居老人的设备，这种**静默失效**比误报危险得多 —— 误报用户会拔电源，静默失效用户根本不知道。

### 0.5 报警历史记录

```c
#define APP_ENABLE_LOG   1       /* 1 = 记录报警历史（需要 RTC + 内部 FLASH） */
#define APP_LOG_MAX      64      /* 最多 64 条，满了覆盖最早的 */
```

| 项 | 说明 |
|---|---|
| 存哪里 | **内部 FLASH 最后一页 0x0807F800**，不占引脚、不走总线 |
| 存什么 | 时间（年月日时分秒）+ 原因（TEMP/HUMI/LIGHT 组合）+ 当时的温度/湿度/光照 |
| 存多少 | 64 条，环形覆盖；每条 16 字节 + CRC16，头部另有魔数 + CRC |
| 什么时候写 | **只在"报警一开始"写一次**（不写心跳、不写正常数据、不写间歇期） |
| 怎么看 | **KEY1** 进历史页翻页；**KEY0** 返回主页；按 KEY1 时同时把全部记录打到串口 |
| 时间戳 | RTC（PC14/PC15 晶振）。装 CR1220 纽扣电池 → 掉电继续走；不装 → 每次上电从**固件编译时间**开始 |

**为什么用内部 FLASH 而不是板载 24C02**

1. 24C02 挂在 PB6/PB7，和 SHT30 的软件 I2C 是同一条总线 —— 再写一套软 I2C 驱动既浪费代码，
   又有把正在稳定工作的 SHT30 读坏的风险；
2. 内部 FLASH 不占引脚、不走总线，`Drivers\BSP\STMFLASH`（官方实验31 移植）已经写好；
3. STM32F103ZET6 的页大小正好 2KB，最后一页存 64 条只用到 1040 字节，还余一半。

代价是擦写寿命（内部 FLASH 约 1 万次，24C02 是 100 万次）。按每天报警 3 次算 1 万次能用 9 年，
而且只在报警瞬间写一次 —— 这个量级完全够。

> ⚠️ **两点要知道**：
> 1. 写一次历史要"整页擦除 + 整页写回"，约 80 ms，这期间 CPU 被 FLASH 控制器挂住，
>    串口收到的字节可能丢（丢的都是 OneNET 的 QoS0 回执，无影响），SysTick 也会少计一拍；
> 2. 如果在这 80 ms 中间掉电，**整页记录会一起丢**（不是丢一条）。上电后头部 CRC 校验不过，
>    会当作空库重新开始，不会显示出乱码记录。
>
> 记录**不会**被重新烧录固件清掉（ISP 只写 hex 覆盖到的区域）。想清空：串口里目前没有指令，
> 可以在 `app_main()` 初始化处临时调一次 `app_log_clear()` 烧进去跑一次，再改回来。

## 1. 数据流

```
 温湿度传感器       ┐
  DHT11 (PG11)     │
   或              ├─► STM32F103ZET6 ──┬─► TFTLCD (FSMC)   本地实时显示  ← 核心，始终工作
  SHT30 (PB6/PB7)  │   72MHz / HAL     │
 光敏 LS1 (PF8)    ┘                   └─► USART3 (PB10/PB11) ─► ESP8266 ─► WiFi 2.4G
   ADC3_IN6
                                                        （APP_ENABLE_NET=1 时才启用）│
                                                   MQTT over TCP :1883              │
                                              mqtts.heclouds.com ◄──────────────────┘
                                                   OneNET「MQTT 物联网套件」
                                           数据流: temp / humi / lux

 报警发生时 ──► RTC(PC14/PC15 晶振) 取时间戳 ──► 内部 FLASH 最后一页(0x0807F800)
                                                  保存 64 条历史，KEY1 翻页回看
```

串口 1（PA9/PA10，板载 CH340C）输出全部调试日志，115200 8N1。
按键：**KEY0 = 报警消音（历史页里当"返回"用）**，**KEY1 = 进入/翻动报警历史页**。

> **关于 `Core\`**：官方例程是手写工程，用户代码放 `User\`；本工程由 STM32CubeMX 生成，
> CubeMX 固定往 `Core\Inc`、`Core\Src` 写，并会重写 `Projects\MDK-ARM\atk_f103.uvprojx`。
> 因此这里保留 CubeMX 的 `Core\`，只把**自写业务代码**放进 `User\App\`，两者互不干扰。
> **代码里的 `#include "./BSP/..."`、`"./App/..."` 一个字都不用改**：包含路径里挂了
> `../../Drivers/` 与 `../../User`，它们分别解析到 `Drivers\BSP\...`、`User\App\...`，
> 与官方例程的做法一致。

## 3. 引脚占用（已逐脚核对官方 IO 分配表）

| 功能 | 引脚 | 备注 |
|---|---|---|
| USART1 调试 | PA9 / PA10 | 板载 CH340C，**P3 跳线帽必须插上** |
| USART3 ↔ ESP8266 | PB10 (TX) / PB11 (RX) | 杜邦线交叉连接 |
| 光敏 LS1 | PF8 = ADC3_IN6 | 板载，免接线 |
| DHT11 | PG11 | 板载 U4 座自带 4.7K 上拉 |
| SHT30（可选） | PB6 = SCL / PB7 = SDA | 软件 I2C，与板载 24C02 共总线；地址 0x44 vs 0xA0 不冲突，板载已有 4.7K 上拉 |
| 蜂鸣器 BEEP | PB8 | 板载有源蜂鸣器，高电平鸣叫，免接线 |
| KEY0 | PE4 | 板载按键，上拉输入，按下为低，用于报警消音 / 历史页返回 |
| KEY1 | PE3 | 板载按键，上拉输入，按下为低，用于进入与翻动报警历史页 |
| LED0 / LED1 | PB5 / PE5 | 运行与联网指示（低电平点亮） |
| TFTLCD | FSMC：PD0/1/4/5/8~10/14/15、PE7~PE15、PG0/PG12、PB0(BL) | 免接线 |
| SWD 下载 | PA13 / PA14 | |

| RTC 晶振 | PC14 / PC15 | 板载 32.768kHz 晶振；VBAT 座建议装 CR1220 纽扣电池 |
| RTC VBAT | VBAT | 装电池后掉电时间继续走；不装则每次上电从固件编译时间开始 |

未占用：PA2/PA3（RS485）、PA11/PA12（CAN/USB）、PA15/PB3/PB4（JTAG）、PB6/PB7（24C02）、
PB12~PB15（W25Q128）、PC0~PC7（摄像头/OLED）、PC8~PC12/PD2（TF 卡）。
**不需要拔任何跳线帽。** 报警历史存**内部 FLASH**（最后一页 0x0807F800），不占用任何引脚。

## 5. 几个关键设计决策

0. **采集/显示与联网解耦**
   主循环里"读传感器 → 刷 LCD"是**无条件执行**的；联网只是一个每轮推进一步的
   状态机（`net_step()`），失败后 15 秒重试。这样即使一条网线都没接，
   板子插上电就能正常显示数据，不会出现"卡在联网界面"的现象。

1. **SHT30 用软件 I2C，不用 F1 的硬件 I2C**
   STM32F1 的硬件 I2C 外设有已知的总线锁死问题（ST 官方 errata），很多人在 F103 上
   宁可软件模拟。正点原子官方的 24C02 例程在同样这两个脚（PB6/PB7）上用的也是软件 I2C。
   SHT30 每 0.5 秒才读一次，100 kHz 软件 I2C 完全够用，还省掉一个外设的初始化与
   总线恢复逻辑。引脚与地址都写在 `Drivers\BSP\SHT30\sht30.h` 顶部，换脚只改 4 个宏。

2. **温湿度统一用 0.1 为单位传整数**
   DHT11 本身只有整数分辨率，SHT30 是 16 位。统一成 `int16_t` 的 0.1 单位后，
   界面能显示 `26.5 C`，而 F103 没有 FPU —— 全程整数运算，不用链入浮点库。
   SHT30 的换算 `T = -45 + 175·raw/65535` 被改写成 `-450 + 1750·raw/65535`。

3. **主循环改成 20 ms 节拍**
   按键必须比采样周期快，否则按一下要按住半个采样周期才认。现在主循环 20 ms 跑一轮：
   `alarm_task()`（扫 KEY0 + 驱动蜂鸣器）与 `net_step()` 每轮都跑，
   采集/刷屏/上报每 `APP_SAMPLE_PERIOD_MS`(500 ms) 跑一次。互不阻塞。

4. **KEY0 消音是"锁定到恢复正常"，不是"停 10 秒"**
   如果 KEY0 只是把蜂鸣器关掉，0.5 秒后新一轮采样发现仍然越界，立刻又响，按键等于没用。
   所以消音会一直保持到所有参数回到正常范围，此时再自动解除，下次越界能重新报警。

5. **ESP8266 走 AT + TCP 透传，MQTT 由 STM32 自己组包**
   不依赖 `AT+MQTTxxx` 指令，因此对模块 AT 固件版本没有要求（老固件同样可用）。
   进入透传后串口是二进制透明的，MQTT 报文里的 `0x00` 不会被吞。

6. **token 在 PC 端算一次后写死进固件**
   `password = token`，算法为 HMAC-SHA1 + Base64 + URL 编码。`et` 设到 2033 年，
   因此 STM32 上不需要跑加密库，省下大量 Flash 与代码复杂度。

7. **上报载荷不带时间戳**
   OneNET 数据点 `t` 字段可选，不带则按到达时间入库 → **免 RTC、免 SNTP**。

8. **所有业务代码放在 `User\App\` 与 `Drivers\BSP\`，并由 `app_main()` 统一入口**
   `Core\Src\main.c` 只在 `USER CODE BEGIN 2` 里加了一行 `app_main();`，
   所以**随时可以用 CubeMX 重新生成代码而不会丢失业务逻辑**
   （重新生成后只需确认 Keil 工程里 app_main.c 等文件仍在分组中）。

9. **BSP 驱动尽量照抄官方源码**
   LCD / DHT11 与正点原子官方例程逐字节一致，出问题时可直接对照官方文档，
   只有 `lsens.c`（底层换成 `hadc3`）与 `esp8266.c`（新写）是本工程自己的。

10. **屏幕文字全部为 ASCII**
   官方字库只有 ASCII 点阵，`lcd_show_string` 遇到 >0x7E 的字节会立刻截断，
   所以界面上不出现中文。

11. **保活必须"等应答"，不能只看"写成功了没有"**
    QoS0 的 PUBLISH 和只判断发送缓冲的 PINGREQ 都有同一个毛病：串口写成功 ≠ 数据到了平台。
    所以 `mqtt_ping()` 改成发完 `PINGREQ` 真的去等 `PINGRESP`（`0xD0 0x00`），
    连续 2 次等不到就判链路故障并重连。**这是全工程唯一能发现"静默断线"的地方。**

12. **上线以后必须持续排空接收缓冲**
    不然 768 字节环形缓冲只涨不落，满了以后 `CLOSED` / `PINGRESP` 全被 ISR 丢弃，
    第 11 条的检测也就无从谈起。主循环每 20 ms 调一次 `mqtt_poll_rx()`。

13. **重连先复位模块，并允许重新扫描波特率**
    模块可能停在透传 / 半开连接等残留状态，直接重发 AT 常常一直失败，所以第 2 次建链起先 `AT+RST`；
    模块若因供电抖动或自身看门狗复位，波特率会回到默认值，而 `g_baud_scanned` 一旦置 1 就
    再也不会重扫 —— 那种情况下会**永久连不上**，所以连续失败 `APP_NET_FAIL_RESCAN` 次后重新全扫描。

14. **读 DHT11 期间关掉 USART3 中断**
    DHT11 判 `0/1` 靠 `delay_us(40)` 之后读引脚电平，而 `0` 的高电平只有 26~28 µs；
    115200 下 USART3 每约 87 µs 进一次中断，会把采样点推后，把 `0` 读成 `1`（表现为偶发 CRC 失败）。
    只关 `USART3_IRQn` 一个中断源、不动 SysTick，所以 `HAL_GetTick()` 与 `delay_us()` 不受影响。

15. **报警阈值分两级，且"响"和"提示"必须分开**（本轮新增，会改变行为，务必知悉）
    原来的 20~25 ℃ / 50~60 % 是"舒适区"，不是"危险线"。冬天室温 18 ℃、夏天 29 ℃ 都会持续报警，
    老人会直接拔电源 —— 报警功能归零。现在拆成两级：超出舒适区只在 LCD 上变黄 + 打 `warnT`，
    超**危险区**（10 ℃/32 ℃、25 %/85 %、光敏饱和）才响。医学上真正该报的是**低温**，
    独居老人冬天舍不得开暖气，这才是低体温风险的来源。
    代价是**报警触发点变了**（20/25 → 10/32），这是产品决策，不是技术优化。

16. **两级判定共用一个确认窗计时器，但迟滞各管各的**
    `alarm_eval()` 里"危险判定永远用危险边界、舒适判定永远用舒适边界"，
    迟滞只对**当前所处那一级**的恢复边界内收。所以温度从 35 ℃（危险，在响）降到 30 ℃
    （超出舒适区、还在危险区内）时会正确地**降级成黄色提示**，而不是继续响、也不是直接变蓝。

17. **报警历史存内部 FLASH 而不是板载 24C02；按键扫描集中到一处**
    24C02 与 SHT30 共用 PB6/PB7 软 I2C，再写一套驱动有把 SHT30 读坏的风险；
    内部 FLASH 不占引脚、官方 BSP 已现成。另外把 `key_scan()` 从 `app_alarm.c` 挪到
    `app_main.c` 的 `app_periodic()`，因为 KEY1 要用来翻历史页 —— 让报警模块自己去扫键，
    会和翻页抢同一个返回值。`alarm_task()` 现在只负责计时停响与蜂鸣器电平。

18. **LCD 行缓存去重 + 报警整屏闪烁**
    主循环每 500 ms 刷一遍所有行，而绝大多数时候内容没变；`ui_show()` 内部做"内容+颜色没变就不写屏"，
    省 FSMC 带宽、也少打扰网络等待期间的服务回调。报警时在此之上叠加整屏红底/白底交替闪烁
    （文字自动换成高对比色），代价仅是 `User\App\app_main.c` 里几十行，不影响报警时序与阈值。

## 8. 验收要点

> 下表即为验收脚本；本轮（P0~P3）实测结果见 §9。

**基本验收（`APP_ENABLE_NET = 0`，不需要 ESP8266 / OneNET）**

1. Keil 全量编译 0 Error / 0 Warning；
2. 串口 115200 打印 `TH   : SHT30 detected`（或 `DHT11 detected`）
   与 `LCD  : id=xxxx  480x320  font=32/24`；
3. 串口连续打印 `DATA SHT30 temp=26.5 humi=55.3 lux=73`；
4. LCD 显示大字号界面（3.5" 屏为 32 号字），`Temp / Humi / Light` 每 0.5 秒刷新，LED1 同步闪烁；
5. 遮住 / 照亮光敏电阻，`Light` 数值随之变化；
6. 拔掉温湿度传感器，`Temp/Humi` 变成 `--.-`，传感器行变红显示 `read fail` 或 `not found`；
7. **危险区报警验收**：把 SHT30 攥在手心里捂热（人体 33~35 ℃，正好越过 32 ℃ 危险线），
   或用电吹风/暖手宝加温 —— **连续越界约 3 秒后**蜂鸣器响、
   **LCD 整屏红底白字与白底彩字交替闪烁**、对应数值行与 `Alarm` 行变红，10 秒后自动停。
   （光照路径也可：强光手电贴近 LS1 直照，让串口 `cdm2=` 打到 19900 以上才到危险级。）
8. **两级阈值验收（本轮最重要的一条）**：把传感器放到 28 ℃ 以上但不到 32 ℃（例如 30 ℃），
   或湿度调到 70 % 以上但不到 85 %，或把光敏放到明亮处（`cdm2` 超过 4000 但远不到 19900）
   —— 应该**只有黄字和 `warnT`/`warnH`/`warnL`，蜂鸣器一声不响**；继续升到危险区才响。
   这一步验证的是"不再误报"。
9. **误报抑制验收**：让温度在 32.0 ℃ 附近反复摆动 —— 不应出现"响 10 秒停 10 秒"的无限循环；
   用手机手电筒快速扫一下光敏（不足 3 秒）—— 不应报警。
10. **KEY0 验收**：报警响起时按一下板上 KEY0，蜂鸣器应立即停、屏幕回到白底，
   `Alarm` 行变黑并带 `mute`；松开手让数值回到正常范围后，消音自动解除，再次越界会重新报警。
11. **报警历史验收**：串口应打印 `RTC  : ok  now 2026-09-22 ...` 与
   `LOG  : N record(s) loaded from 0x0807F800`；触发一次报警后串口出
   `LOG  : saved #1 ...`；按 **KEY1** → LCD 切到 `Alarm Log 1/1  total 1`，
   并同时把全部记录打到串口；按 **KEY1** 再按（只有一页时）→ 回主页；按 **KEY0** → 回主页；
   **掉电重启后记录应还在**（这是这条功能的核心意义）。

**扩展验收（`APP_ENABLE_NET = 1`，需要 ESP8266 + OneNET 参数）**

12. LCD 依次显示 `WiFi : OK` → `Cloud : online`；
13. `Sent` 计数每 5 秒 +1；
14. OneNET 控制台设备显示**在线**，`temp` / `humi` / `lux` 三条数据流出现历史数据点；
15. **DHT11 抗干扰验收**：联网上报期间串口不应再出现 `DHT11: CRC fail`
    （USART3 收数中断已避开单总线时序）；
16. **报警历史与断线共存验收**：`APP_ENABLE_LOG = 1` 时联网上报照常，
   报警瞬间那一次 FLASH 整页擦写（约 80 ms）不应导致 MQTT 掉线（最多丢一两个 QoS0 回执）。
17. **断线检测验收**：设备在线后把路由器断电或关掉热点，串口应在
    **约 1 分钟内**依次打印 `MQTT: ping no answer (1/2)` → `MQTT: link lost (2 pings no answer), reconnect`
    → `NET FAIL: Cloud : link lost`，LCD 的 `Cloud` 行变红；恢复热点后自动重新 `WiFi : OK`
    → `Cloud : online`，`Sent` 计数继续增长。
    > 旧版在这里会**一直显示 `Cloud : online` 且 `Sent` 继续增长**，实际数据早就断了。

### 9.2 遗留事项（不影响验收结论）

1. **光照通道标定**：`APP_LUX_FULL_SCALE_CDM2` 仍为默认 `20000`，属估算值。
   若后续用手机照度计实测，可据此调整该值，或把 `APP_COMFORT_LUX_MAX_CDM2` 改 `0` 关闭光照提示。
2. **VBAT 纽扣电池**：RTC 依赖 VBAT 座内的 CR1220 维持走时。未装电池时每次上电时间回落到
   固件编译时刻（串口会打 `[clock not battery-backed]`），历史记录时间戳仅可作相对参考。
3. **存储介质选择**：本功能实现用**内部 FLASH 末页**（`0x0807F800`）而非 24C02 ——
   24C02 与 SHT30 软件 I2C 共用 PB6/PB7，另起一套软 I2C 有干扰 SHT30 的风险；
   内部 FLASH 不占引脚。如需改用 24C02，只需替换 `app_log.c` 的存储层，记录格式与 UI 不动。
